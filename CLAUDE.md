# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

`home-budget` — a home budget app built on the "Claude Course TanStack Starter" (course: *Claude w pigułce – dla programistów i nie tylko*). Stack: TanStack Start (React 19, SSR, Vite 7), TanStack Router (file-based), TanStack Query, Drizzle ORM on SQLite (better-sqlite3), Tailwind CSS v4, shadcn/ui, Biome, Vitest. Package manager: npm.

## Commands

```bash
npm run dev            # dev server on http://localhost:3000
npm run build          # production build
npm run test           # vitest run (all tests)
npx vitest run tests/utils.test.ts   # single file
npx vitest run -t "merges"           # tests matching a name
npm run lint           # biome lint
npm run check          # biome lint + format + organize imports (writes)
npm run format         # biome format (writes)

npm run db:generate    # generate SQL migrations from src/db/schema.ts into ./drizzle
npm run db:migrate     # apply migrations
npm run db:push        # push schema directly (dev)
npm run db:studio      # Drizzle Studio

npx shadcn@latest add <component>   # adds to src/components/ui
```

There is no separate typecheck script; use `npx tsc --noEmit`.

## Environment

`DATABASE_URL` (path to the SQLite file, e.g. `dev.db`) must be set in `.env.local` or `.env`. `src/db/index.ts` throws at import time if it is missing, and `drizzle.config.ts` loads it via dotenv. `dev.db` and `*.local` are gitignored. Project permissions deny reading `.env*` files.

## Architecture

- **Routing**: files in `src/routes/` are routes; `src/routes/__root.tsx` is the HTML shell (`shellComponent`) that wraps every page with `TanStackQueryProvider`, `Header`, `Footer`, devtools, and an inline theme-init script. `src/routeTree.gen.ts` is generated by the router Vite plugin — never edit it by hand (it is excluded from Biome and read-only in VS Code).
- **Router + Query wiring**: `src/router.tsx` creates the router with context from `getContext()` (`src/integrations/tanstack-query/root-provider.tsx`), which holds a singleton `QueryClient`. Routes receive `{ queryClient }` via router context (`createRootRouteWithContext<MyRouterContext>`), so loaders can prefetch with `context.queryClient`.
- **Server code**: the DB client (`src/db/index.ts`) uses better-sqlite3 and must only run on the server — access it from `createServerFn` handlers or route `server.handlers` (API routes), never directly from components. Schema lives in `src/db/schema.ts` (currently only a starter `todos` table).
- **Styling**: Tailwind v4 configured in CSS (`src/styles.css`, no tailwind.config). It defines two token sets: the app's own theme variables (`--sea-ink`, `--lagoon`, `--line`, etc.) plus helper classes (`page-wrap`, `island-shell`, `island-kicker`, `display-title`, `nav-link`, `rise-in`) used by existing pages, and the shadcn tokens (`--background`, `--primary`, …). Dark mode is class-based (`.dark` on `<html>`), driven by `ThemeToggle` + `localStorage('theme')`. Use `cn()` from `#/lib/utils` to merge classes.

## Conventions

- Import alias: `#/*` → `src/*` (defined in both `package.json` `imports` and `tsconfig.json`; `@/*` also works but `#/` is what shadcn and tests use).
- Biome formatting: tabs, double quotes. Biome only covers `src/`, `tests/`, and `vite.config.ts`.
- TypeScript is strict with `noUnusedLocals`/`noUnusedParameters` and `verbatimModuleSyntax` — use `import type` for type-only imports.
- Tests live in `tests/` (not colocated) and run under Vitest with jsdom/Testing Library available.
- UI copy in the starter is mixed English/Polish.
